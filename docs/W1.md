# W1: projects, runs and data flow

What the owner and Claude agreed in the W1 interview on 2026-11-26. The words are defined in [GLOSSARY.md](../GLOSSARY.md); the two decisions that are hard to reverse are in [adr/0001](adr/0001-active-project-in-localstorage.md) and [adr/0002](adr/0002-mappings-only-inside-the-active-run.md). Batches W1a and W1b in [ROADMAP.md](ROADMAP.md) build this.

LabKit is for students only. Teachers do not set anything up.

## What exists today (measured before W1)

- All tool inputs are in one flat map `labkit:v1:inputs` keyed by element id, plus `labkit:v1:tables`, `labkit:v1:proto`, history `labkit:v1:hist` and bench `labkit:v1:bench` / `labkit:v1:benchnotes`.
- *Sessie opslaan* downloads every `labkit:` key plus the IndexedDB gel library (`labkit-gels`, at most 30 gels) as one file; import overwrites everything and reloads. The project name is only a label for the filename and printouts.
- The seven werkstromen (`WF` in `src/legacy/nt/99z_ux.js`) only navigate between tools; nothing passes data.
- *Stuur door naar* (`SEND` in `src/legacy/nt/99_app.js`) copies one result at a time, e.g. DNA concentration → PCR template volume `q-t`.
- A share link carries one tool (`toolSnap`); a QR is shown up to about 2300 bytes.

## Projects (S118)

- A project holds the tool inputs, tables, history, bench checklists and bench notes, the sample-name list, its runs, its gels and one notes page. Preferences stay global: pins, favourites, recent, usage, expert mode, collapsed menu, phase filter, language, theme.
- One project is active. Switching saves the current one and reloads the page (adr 0001).
- On first start after the update, everything already in the browser becomes the project *Mijn project*, its current werkstroom becomes its first run. Nothing is lost.
- A project chip in the top bar shows the active project in every tool. Tapping it opens a panel: the project list with storage used per project and free space, new, rename, delete (also deletes its gels; asks first), *Project exporteren*, *Project importeren* (adds a project, never overwrites), and *Alles back-uppen* (today's full dump).
- Gels carry their project and run. The gel library shows the active project's gels grouped by run, with *toon alle projecten*. At most 30 gels per project.
- The notes page has dated notes; each note records the run that was active. Notes go into the Rapport.
- Storage: the active project in localStorage as now, inactive projects and runs in IndexedDB, persistent storage requested once on the website. The panel shows use and free space.

## Runs

- A run is one use of a werkstroom in a project, with an editable name (default the werkstroom name, then "(2)", "(3)"). It has its own copy of the inputs of its tools, so the same werkstroom can run twice in one project (week 3 and week 4).
- A project can hold several runs. One is active; the workflow bar shows it and switches between runs (with a reload). A new run starts empty, or as *kopie van …* an earlier run.
- With no run active, tools show the project's losse invoer, and nothing fills itself.
- The workflow list on the start page and in the bar is headed *Mijn werkstromen* and shows runs by name; the word "run" never appears in the app.

## Data flow (S117)

- Mappings act only between tools of the active run, live: when a source changes, every downstream field that still has an auto value follows. Step order does not matter; the source only has to be in the run (adr 0002).
- A field with an auto value just shows the value. Clicking into it to edit stops the live feed for that field; a small button next to it switches it back to auto. That choice is saved with the run.
- *Stuur door naar* stays as it is, inside and outside runs.
- First mappings, for *Van DNA tot gel*:
  1. DNA concentration → PCR template volume (`q-t`, the same calculation as the existing send)
  2. product size of the in-silico PCR in the primer tool → Gelplanner expected sizes per sample lane
  3. the sample-name list → Gelplanner lane names
  4. Gelplanner → gel editor expected bands (already exists through `gp-tbl`)
- Later: loading volume from concentration, and chains such as cell count → seeding → transfection, on the same mechanism.

## Own werkstromen and course templates (S119)

- *Werkstroom maken*, from the start page and the workflow bar: a name, tools picked from a searchable list, reordered by drag or ↑/↓ buttons, saved in the project-independent list of werkstromen.
- Built-in werkstromen and course templates can be copied and then edited, not changed in place.
- First version ships two or three generic course templates (PCR and gel, cell culture passage, ELISA); the owner supplies the real BML module names and contents later.
- Mappings also work in a student's own werkstroom whenever both tools are in it. Students cannot edit mappings.
- A werkstroom can be shared as a link that adds it to the receiver's list.

## Sharing a run (S120)

- One run: its werkstroom, its step and the inputs of its tools, compressed, without gels or photos. A QR when the link fits, otherwise only the link.
- Opening it creates a new project *Gedeeld: <run name>* holding that run, so it never overwrites anything. A whole project travels as an export file, not a link.

## Search that understands questions (S121)

- In the Ctrl+K palette and the start-page search. Dutch and English phrasing.
- First five calculators: Oplossing ("500 mL 0,9% NaCl", "250 mL 0,1 M Tris"), Verdunning ("1:10 van 50 mL", "10 µM uit 1 mM stock"), Centrifuge ("4000 rpm rotor 10 cm"), Eenheden ("5 mg/mL naar µM"), Molmassa ("molmassa NaCl").
- The tool opens with the fields filled and the note *Ingevuld uit je zoekvraag*. In a run these count as eigen waarden, not auto values.
